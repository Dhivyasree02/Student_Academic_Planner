
# API Documentation
## Student Academic Planner

## 1. Introduction

This document describes the REST APIs used in the Student Academic Planner application. The APIs allow the frontend or an API testing tool such as Postman to communicate with the Spring Boot backend.

## 2. Base URL

When the application runs locally on port 8080:

http://localhost:8080

## 3. Semester Marks API

### 3.1 Save Semester Marks

- HTTP Method: POST
- Endpoint: /api/marks
- Content-Type: application/json
- Purpose: Saves a semester marks record.

Request Body:

```json
{
  "subject": "Java",
  "semester": "Semester 1",
  "marks": 85,
  "totalMarks": 100
}
```

Successful Response:

HTTP Status: 201 Created

```json
{
  "id": 1,
  "subject": "Java",
  "semester": "Semester 1",
  "marks": 85.0,
  "totalMarks": 100.0
}
```

The ID shown is an example. The actual ID is generated by the database.

### 3.2 Retrieve Semester Marks

- HTTP Method: GET
- Endpoint: /api/marks
- Purpose: Retrieves all semester marks records.

Example Response:

```json
[
  {
    "id": 1,
    "subject": "Java",
    "semester": "Semester 1",
    "marks": 85.0,
    "totalMarks": 100.0
  }
]
```

If there are no records, the endpoint returns an empty JSON array.

### 3.3 Delete a Semester Marks Record

- HTTP Method: DELETE
- Endpoint: /api/marks/{id}
- Purpose: Deletes a marks record using its ID.

Example:

DELETE /api/marks/1

Possible responses:

- 200 OK: Record deleted successfully.
- 404 Not Found: Record does not exist.

These responses depend on the implementation of the controller.

## 4. Input Validation

The semester marks API validates the following:

- Subject must not be empty.
- Semester must not be empty.
- Marks must be zero or greater.
- Total marks must be greater than zero.
- Marks obtained must not exceed total marks.

Invalid input returns HTTP 400 Bad Request.

## 5. Error Handling

The application includes a GlobalExceptionHandler class for handling exceptions. The exact exception types and HTTP response formats depend on its implementation.

Common HTTP status codes include:

| Status Code | Meaning |
|---|---|
| 200 OK | Request completed successfully |
| 201 Created | Record created successfully |
| 400 Bad Request | Invalid request data |
| 404 Not Found | Requested record not found |
| 500 Internal Server Error | Unexpected server error |

## 6. API Testing

The APIs can be tested using Postman.

Steps:

1. Start the Spring Boot application.
2. Open Postman.
3. Select the required HTTP method.
4. Enter the endpoint URL.
5. For POST requests, select Body > raw > JSON.
6. Enter the request data.
7. Click Send.
8. Verify the HTTP status and response body.

## 7. Other Application APIs

The project also contains controllers for assignments, examinations, and planner operations.

Their exact endpoint URLs, HTTP methods, request bodies, and response formats must be documented using the mappings and method definitions in AssignmentController, ExamController, and PlannerController.

## 8. Conclusion

The REST API layer enables communication between the frontend and the backend. It allows academic information to be submitted, retrieved, and managed through HTTP requests.
